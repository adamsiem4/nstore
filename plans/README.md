## Findings considered and rejected

- Redirect/email origin built from `Host`/`X-Forwarded-Proto` (`src/server/actions/checkout.ts:66-67`): not worth doing — the header only affects the requester's own Stripe redirect, and on Vercel the platform sets it. Revisit only if self-hosting behind an untrusted proxy.
- Checkout success page and cart-clearing route trust any paid `session_id` (`src/app/api/checkout/return/route.ts`, `src/app/(store)/checkout/success/page.tsx`): by design — the Checkout Session id is an unguessable bearer token, the standard Stripe pattern; guests have no other identity to bind to.
- "Stripe API version is unpinned" (`src/server/services/stripe.ts:12`): false — stripe-node 22.6.2 pins its own API version (`node_modules/stripe/esm/apiVersion.js`), and the webhook re-fetches the PaymentIntent with it instead of trusting the event payload.
- Both hero images carry `fetchPriority="high"` (`src/app/(store)/page.tsx:32-46`): by design and documented in the adjacent comment — the off-theme image is `hidden` and lazy, so it never downloads.
- Catalog search is an unindexed `strpos` scan with no pagination (`src/server/queries/products.ts`): not worth doing at 50 products.
- README "all 22 tests" is stale: false — `bun run test` runs exactly 22 tests at `a89aea0`.
- Footer copyright year can mismatch at New Year (`src/components/layout/site-footer.tsx:75`): not a hydration issue (Server Component). It does become a build error under Cache Components and is handled in plan 006.
- `typescript-language-server` in `devDependencies` is unused by source: not worth doing — editor/agent tooling, dev-only, no runtime surface.
- One Stripe request per order on `/orders` (`src/server/queries/orders.ts:37-47`): a documented, capped shortcut (20 orders, parallel); the real fix is the "persist orders" direction option above, not a patch.
- Missing formatter config and `noUncheckedIndexedAccess`: style choices with a repo-wide diff and no demonstrated defect.
- Return-request and order-status actions throw on an unknown PaymentIntent id instead of returning a friendly error: reachable only with a hand-crafted request; ownership is still enforced.
